# Security Policy

Holdfast handles escrow settlements, payment rails, and customer financial agreements. We take security vulnerabilities seriously.

## Responsible Disclosure

If you discover a security vulnerability or potential exploit affecting Holdfast smart contracts, backend API, or infrastructure, please report it **privately**.

**Do NOT open a public GitHub issue for security vulnerabilities.**

### Contact
- **Email**: `security@holdfast.africa` *(placeholder; monitored by core engineering)*
- **PGP Key**: [Security PGP Public Key Placeholder]

### Information to Include
To help us triage and reproduce the issue quickly, please include:
1. Type of vulnerability (e.g. smart contract reentrancy, authorization bypass, injection, cryptographic issue).
2. Affected components and file paths.
3. Step-by-step reproduction instructions or a minimal proof of concept script.
4. Potential business and financial impact (e.g. fund loss, unauthorized state transition).

### Response Timeline
- **Initial Response**: Within 24 hours of report receipt.
- **Triage & Assessment**: Within 48 hours.
- **Remediation & Patching**: Within 7 business days, depending on severity and network coordination.
- **Coordinated Disclosure**: We will coordinate with the reporter on a public disclosure date once a verified fix has been deployed to mainnet/production.

## Bug Bounty Program
A formal bug bounty program will launch ahead of the Phase 4 mainnet release. Responsible security disclosures submitted before program launch will be recognized in our security hall of fame and prioritized for retrospective rewards.
